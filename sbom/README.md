# Third-party components and licences

This directory lists every third-party component of the repository with its
licence, for each part:

| Part           | What the list is read from                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------- |
| Back Office    | `back-office/package-lock.json`; the vendored Inter font; the container base images                           |
| Contracts      | `contracts/package-lock.json`, `contracts/soldeer.lock`; EBSI's contracts in `contracts/local/ebsi-mock/`     |
| Atest Wallet   | `holder-wallet/yarn.lock`, `holder-wallet/ios/Podfile.lock`; native libraries fetched at build time; fonts    |
| Infrastructure | `infra/ebsi-mock/package-lock.json`; the container images the Compose files run                               |

Each part has two files with the same content:

- `<part>.md`: a readable table of components, versions, licences and use;
- `<part>.cdx.json`: a [CycloneDX 1.6](https://cyclonedx.org/specification/overview/)
  SBOM with package URLs, hashes from the lockfiles, licences as SPDX
  expressions, and the use as the component's `scope` (`required` or
  `optional` for production, `excluded` for development).

**Production** components are what a production install of a part contains:
what its app, images or deployed contracts are built from. For npm and Yarn that
is everything `dependencies` reach. For the wallet that includes build tools,
such as Metro, Babel and lightningcss, that do not themselves ship in the app. **Development**
components only build, test or run the part locally: what only
`devDependencies` reach, and everything that serves only the development stack,
such as the development EBSI service and the local Besu ledger.

The repository's own code is under the MIT License (see each part's
`LICENSE.md`).

## Regenerating

The lists are generated by [`generate.mjs`](generate.mjs) from the lockfiles and
the installed dependencies; it needs Node.js 24 and no network. What no lockfile
records (vendored files, native libraries fetched at build time, container
images, tools) and the few licences packages do not state in SPDX form are in
[`components.json`](components.json), each with the evidence the generator
checks.

After changing a dependency, with its part's dependencies installed:

```sh
node sbom/generate.mjs           # rewrite the lists
node sbom/generate.mjs --check   # CI: fail if a list is out of date
```

A published package's licence never changes for a given version, so the
generator takes a licence it cannot read (a package not installed on this
platform, or a fresh checkout) from the previous list. A new package therefore
needs its dependencies installed once. The generator fails when a component has
no licence, or when the evidence for an entry in `components.json` no longer
holds.

## What the lists do not cover

- **The wallet's Android libraries from Maven.** Gradle resolves them at build
  time from the React Native and Expo modules in the npm list; the repository
  has no Gradle lockfile, and resolving them needs the Android SDK. The native
  libraries that matter for licensing and fetched outside npm (OpenSSL,
  libsodium) are listed with both their iOS and Android sources. For the full
  list, run on a machine with the Android SDK:
  `cd holder-wallet/android && ./gradlew :app:dependencies --configuration releaseRuntimeClasspath`.
- **The Linux packages inside container images.** Images are listed by the
  software they run. `docker sbom <image>` lists the packages of a pulled image.
- **Code vendored inside an npm package.** It is covered by that package's own
  licence and notice files, which are shipped in the package.

## Block explorer

Earlier versions of `infra/besu/besu-qbft-network/` included Web3 Labs'
Chainlens explorer. Its licence allows only internal, non-commercial
evaluation and does not allow redistribution, so it has been removed from the
repository. It is listed below as a development tool that is not distributed.
